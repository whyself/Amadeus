# DSH 0.2.0-rc.2 兼容与功能重复审计

日期：2026-10-02。状态：依赖试升级，尚未完成兼容修复与发布回归。

## 范围与版本

- Amadeus 基线：审计开始时的 `main@b3be9fc`，产品版本 `1.1.3`，DSH `0.1.7-rc.2`。main 在审计期间推进到 `4d4a41e`；本报告仍针对 worktree 保存的 `b3be9fc` 快照，未包含那些新提交。
- 审计分支：`codex/dsh-2-0-rc2-audit`，独立 Codex worktree。
- 目标实际为 npm 的 `@deepseek-ai/dsh@0.2.0-rc.2`。查询时 `latest` 与 `next` 均指向该版本；`2.0.0-rc.2` 不存在。
- 上游旧 tag：`dsh-v0.1.7-rc.2`，commit `477b4f420553e8a52c2fbccc464d7561b239c443`。
- 上游新 tag：`dsh-v0.2.0-rc.2`，commit `639ed015397290b3745d163aafe02ffee4aa3f84`。
- 对比范围包含 rc.1 与 rc.2，不能只读 rc.2 的增量发布说明。

本分支保留根 `package.json`、Login 的 `package.json` 和 `package-lock.json` 的试升级。两个 DSH 直接依赖与 Login 的 WebServer 均固定为 `0.2.0-rc.2`；Cordis `4.0.4`、Schemastery `3.18.4` 保持原版本，依赖解析未发现冲突或遗留 `0.1.7-rc.2` 的 DSH 节点。临时禁用 Reader 队列包装的实验不作为最终源码改动保留。主工作目录没有修改。

## 结论

升级可行，目前没有发现 npm 依赖、启动补丁锚点或认证接口的直接不兼容。已有一个必须处理的 Reader 运行时错误，单元测试和构建不能检出。功能去重的首选是 PDF 选区颜色覆盖，其次是文件树整合；code-server、LaTeX、注释定位、文件传输和 PWA 仍有独立价值。

### 1. 已复现问题：Reader 的旧队列状态读取

位置：`packages/reader/src/client.jsx` 的 `delayQueueDock()`。

```js
props.useSession(state => state.queue.some(item => item.placement === 'queued')
  || state.pendingSubmissions.some(item => item.placement === 'queued'))
```

浏览器控制台实际报告：

```text
TypeError: Cannot read properties of undefined (reading 'some')
slot entry crashed in 'conversation.input.dock'
```

`state.queue` 不属于当前读取方式。上游 `QueueDock.tsx` 使用 `useProjection('inbox')` 取得 `inbox?.['next-turn'] ?? []`，再与 `pendingSubmissions` 合并、去重。对比两个 tag，`QueueDock.tsx` 没有源码差异，因此这是基线已经存在的适配问题，不能归因于 0.2 新增的破坏性变更。

临时移除 `delayQueueDock` 的注册、重新构建 Reader 后，隔离首页不再出现上述异常。建议优先删除这段只为抑制短暂闪烁的包装，或严格复用上游投影、待发送项与去重语义；仅改成 `state.queue?.some()` 会掩盖异常并漏掉真正的队列。

### 2. 没有直接冲突，但应保留回归检查的耦合

| 集成点 | 对照结果 | 后续处理 |
| --- | --- | --- |
| 布局 bundle 补丁 | 新 npm 发布包仍有唯一中心最小宽度与产品标题锚点；现有替换成功 | 保留未知构建拒绝机制。将来用上游品牌配置替代文字替换时另行设计 |
| Lexical IME 补丁 | 新发布包仍匹配 `F = i ? "\\xA0" : A`，Lexical 声明仍为 `^0.49.0` | 不因版本升级直接删除；补丁匹配不等于真实中文输入回归通过 |
| Login 认证 | WebServer、Connection 的相关源码没有变化；`requestRejection`、`authorizeIndex`、`authenticatedUrl` 仍存在 | 保留 Basic/cookie 接管与跨域校验；不要直接换成上游启动 token 登录 |
| code-server WebSocket | 上游 upgrade 仍按精确路径匹配 | 保留 `PrefixUpgradeRoutes`；真实编辑器与扩展 webview 需独立回归 |
| 侧栏控制器 | `mounted` 改为在会话切换的 React 渲染前更新，移除了控制器的 `bind()`；Amadeus 没有调用该方法 | `openTabIn`、`openResourceIn`、`closeIn`、`registerCloseHandler` 仍在；前三者属于实现接口而非 `ISidebarRight` 公共声明，应逐步减少依赖 |
| 编辑器 iframe 生命周期 | 上游仍支持 tab 类型的 `keepMounted`，Amadeus 自行维护 iframe/cache | 这是已有能力重叠，需验证切会话、浮窗、关闭和未保存保护后再决定是否简化 |
| 注释与聊天节点 | `sendSession` 调用签名保留，`user`、`steering`、`assistant-step` keyed slot 与原文定位 DOM 标记仍在 | 上游调整问答与过程分组；回答引用、折叠消息、跨会话定位仍需真会话回归 |
| 收起中间对话 | 上游框架仍沿用相同的 grid 主体；Amadeus 读取内联列宽并覆盖 grid | 自定义收起功能未被原生左右侧栏收起完整覆盖。避免依赖 `.pI_x6G_handle` 等构建生成类名 |
| 注释独立发送 | 上游仍阻止空文本且无附件的普通发送 | 零宽 draft marker 仍有用途；现有公共引用 chip 并未自动替代选区注释协议 |

### 3. 功能重复与保留建议

| 功能 | 0.2.0-rc.2 原生能力 | Amadeus 能力 | 建议 |
| --- | --- | --- | --- |
| PDF/Office 文字选区 | rc.1 起改用 `--dsw-alias-bg-document-selection`，适配浅/深主题 | Reader 注入 `[data-pdf-text] ::selection` 的固定 RGBA 与 `!important` | 明确重复；移除强制覆盖前检查浅/深主题，以恢复原生 token 的作用 |
| PDF 工具栏 | 原生缩放、fit-width、页码等 | 自定义控件已在 Amadeus 1.1.1 删除 | 已完成去重，不再加第二套 |
| 文件浏览树 | 原生目录树、目录监听、资源打开；rc.2 加入目录打开动作 slot | 接管 `kind: 'files'`，增加上传文件/文件夹、ZIP 下载、版本确认删除、编辑器入口 | 部分重复。注册表明确允许 extension 覆盖 builtin，此处不是重复注册报错 |
| 文件页原生增强 | `sidebar.right.tab.files.actions` 可扩展标题栏动作；原生树仍不提供上传、ZIP 下载、版本确认删除 | Amadeus 自己渲染整个文件页，没有渲染新增动作 slot | 当前接管会隐藏原生目录“在应用中打开”等动作。Docker 打开的是服务端应用，不等于浏览器电脑；如需整合，应处理这一语义 |
| code-server 与 LaTeX | DSH 有预览、终端、改动审阅和宿主应用打开 | 完整 VS Code 工作台、扩展桥接、TeX Live、latexmk、LaTeX Workshop | 主要能力不重复，继续保留 |
| 选区注释 | 原生 `@file/@session` 引用与输入 reference chip | 精确选区、可选评论、页码/行号/消息定位、回答引用链接 | 有概念重叠，能力不等价；保留注释协议和定位，可考虑以后复用 chip 呈现 |
| 网页浏览器、Office 预览、终端、改动审阅 | 原生提供 | 当前主要启用或增强原生功能 | 沿用原生实现；不要重复开发完整模块 |
| 聊天性能 | 更新局部动画、运行用时、文字与过程间距 | 已完成消息的 `content-visibility:auto` | 作用不同；不能因“优化动画”发布说明就删掉离屏布局优化 |
| 主题与延迟 | 原生主题、连接状态 | code-server 独立外观与 RTT 数值 | 编辑器主题独立于 DSH，RTT 也不是原生断线提示的替代；保留 |
| PWA | 检查到的相关上游集成未替代 Amadeus manifest/service worker | 安装、资源缓存、网络接口排除 | 保留，并检查新静态资源与 module URL 的缓存更新 |

文件树建议先保留完整扩展页，再决定整合方式。新增标题栏动作 slot 适合上传或 ZIP 操作，但不能直接承载 Amadeus 现有的逐行编辑/删除按钮；要合并树还需要逐行扩展点或一次明确的交互调整。接管页也可以独立接入目录监听，避免重复实现全套原生树。

### 4. 升级时需要处理的上游行为变化

- 自动化任务移至可选 `@deepseek-ai/dsh-experimental-schedule-bundle`。默认 Web 组合删除 `time-context`、`schedule`、`ui-schedule` 三个旧条目，新 bundle 插回这三个条目。Amadeus 当前没有显式开启它们；已有用户若通过旧 patch 开启，应迁移到 bundle 并确认任务存储仍被读取，不应依靠旧 id 开关。
- 模型目录更新到 pi-ai `0.87.1`，上游说明部分旧模型 ID 已删除。正式迁移应检查保存的模型选择，不必改动 Amadeus 的编辑器或文件插件。
- Web 与 Desktop 的工作过程展示默认值分开，Web 缺省为 `detailed`，Desktop 为 `standard`。这是行为变化，不是插件 API 消失；应在 README 或升级说明记录用户看到的差异。
- 上游加入 plan 审阅恢复、异步问答、shell 行为修复。Amadeus 没有对应的完整独立实现，应沿用这些能力，并验证 Reader 的节点包装没有影响原生显示。

## 建议实施顺序

1. 保持本分支三个依赖文件的统一固定版本；修复或移除旧队列包装，再完成真实浏览器入口回归。
2. 删除 PDF 选区固定颜色覆盖，检查浅/深主题；保留现有 IME 和布局补丁的版本锚点保护。
3. 确定文件树继续接管还是整合原生树；保留文件传输与安全确认，明确是否保留服务端“在应用中打开”。
4. 收敛 Sidebar 实现接口、生成 CSS 类名与节点包装依赖；补充 DSH runtime peer 范围。目前四个插件仅声明 Cordis peer，无法表达自身支持的 DSH 版本。
5. 在复制的数据卷上回归历史会话、可选 schedule、模型选择，再验证真实 code-server、LaTeX、PDF、注释与 PWA。完成后更新 README/CHANGELOG 并作为后续版本发布。
